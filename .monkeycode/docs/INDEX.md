# AutoTurnitin 自助检测平台

## 背景
- 市场上大量用户希望快速了解文稿相似度结果，但官方 Turnitin 入口操作复杂、等待时间不可控。
- 现有 https://www.turnitin-service.com/similarity 前端提供了无登录、直接提交检测的体验，用户希望一比一复刻界面与流程。
- 运营方需要一个完全可控的后台来接收上传、手动上传检测报告，并向用户同步状态。

## 目标用户
- **终端提交者**：个人学生、内容创作者，需要一次性检测稿件相似度。
- **运营管理员**：AutoTurnitin 团队内部成员，负责生成检测码、导入稿件到官方渠道、上传报告以及维护运营数据。

## 价值主张
- 复制原站的轻量提交体验，无需注册即可上传文档并输入检测码提交。
- 通过检测码与提交记录绑定，实现后台人工处理 + 前端自动提示的闭环。
- 提供后台管理中心：检测记录、检测码、订单/任务、管理员账号、运营统计、任务重试。
- 严格的 24 小时数据保留策略，降低存储成本并提升合规性。

## 功能范围（MVP）
1. **自助检测页面**：上传文档、填写基本信息、输入检测码、提交表单。
2. **提交状态提示**：提交后展示灰色不可点击的“下载查重报告/下载 AI 报告”按钮与进度提示；当后台上传报告并更改状态后，按钮变为可点击的蓝色并提示 24 小时内下载。
3. **检测码校验**：前端在提交前校验检测码是否存在/可用，后台可批量生成、导入、失效处理。
4. **报告交付**：管理员在后台上传查重/AI 报告文件并手动更新状态，前端实时（或轮询）获取可下载链接。
5. **运营后台**：
   - 检测记录：筛选、排序、批量检测码查询、详情、报告下载、删除。
   - 订单/任务：追踪每个检测请求的费用来源与状态。
   - 管理员账号：多角色、多账号登陆系统。
   - 检测码管理：生成、导入、作废、分配。
   - 任务重试：当官方渠道失败时记录并重新安排。
   - 运营统计：提交量、完成率、平均周转时间等 KPI。
6. **系统监控**：后台仪表盘显示存储容量、待处理数量、异常任务。

## 关键约束
- 不对接官方 API，由管理员人工查询官方系统并上传报告。
- 报告文件需在 24 小时后自动删除（含 OSS 与数据库记录）。
- 仅当检测码有效且未使用时允许提交。
- 前端需忠实复刻参考站点的布局、动效和文案（支持多语言配置）。
- 需考虑高峰期并发上传（至少 50 并发）与文件大小上限（默认 30MB，可配置）。

## 非目标
- 不提供在线支付/结算（可在后续版本集成）。
- 不在 MVP 中实现自动化 Turnitin 查询或 API 对接。
- 不面向第三方开放 API。

## 开发里程碑
1. **M1 - 提交链路**：完成前端仿站、检测码校验、提交存储与状态轮询。
2. **M2 - 后台管理**：完成检测记录表格、状态编辑、报告上传与下载权限控制。
3. **M3 - 运维能力**：实现统计图表、任务重试、系统监控告警、自动清理策略。
